
# INDEXEDファイルのロック仕様

## SELECT句のLOCK MODE

- SELECT句のLOCK MODEにはAUTOMATICかMANUALのみ指定可能である。
- 省略した場合のLOCK MODEのデフォルト値はMANUAL
  - コンパイル時に`-lock-mode-automatic`を指定した場合、LOCK MODEを省略した場合のデフォルト値はAUTOMATICになる。

## レコードロックの動作

- OPEN I-Oでファイルを開き、WITH NO LOCKもWITH LOCKも指定されないREAD文を実行したとき
  - SELECT句のLOCK MODEがMANUALの場合、当該レコードをロックしない
  - SELECT句のLOCK MODEがAUTOMATICの場合、当該レコードをロックする
- OPEN I-Oでファイルを開き、WITH LOCK指定のあるREAD文を実行したとき、当該レコードをロックする
- OPEN I-Oでファイルを開き、WITH NO LOCK指定のあるREAD文を実行したとき、当該レコードをロックしない
- レコードロックにより処理が失敗した場合、ファイルステータスが51となる

## ファイルロックの動作

- OPEN OUTPUTで開いたときに、当該ファイルにファイルロックがかかる
- ファイルロックにより処理が失敗した場合、ファイルステータスは61となる

## 古いバージョンのINDEXEDファイルを新バージョンに対応させる。

古いバージョンのINDEXEDファイルは、直接最新バージョンのopensource COBOL 4Jでは使用できません。
古いバージョンで作成したINDEXEDファイルを新バージョンに対応したものに変換するには、以下のコマンドを実行してください。

```sh
cobj-idx migrate <<INDEXEDファイル>>
```

これにより、指定したINDEXEDファイルが新バージョンに対応したものに変換される。

## INDEXEDファイルのロックを解除する

下記のコマンドで、INDEXEDファイルにかかったファイルロックとすべてのレコードロックを解除できる。

```sh
cobj-idx unlock <<INDEXEDファイル>>
```

## 古いバージョンのINDEXEDファイルを開いたときの動作

古いバージョンのINDEXEDファイルを開こうとした場合、ファイルステータスが92となる。
## INDEXEDファイルのジャーナルモード

INDEXEDファイルはSQLiteをバックエンドとしており、opensource COBOL 4J 2.1.0 以降は既定でWAL(ライトアヘッドログ)ジャーナルモードを使用する。
モードは環境変数 `COB_INDEXED_JOURNAL_MODE` で選択でき、`WAL`(既定値)と `DELETE` を指定できる。
`DELETE` を指定すると以前のバージョンと同じロールバックジャーナルの動作に戻る。詳細は
[環境変数リファレンス](./environment_variables_JP.md) を参照のこと。

ジャーナルモードはSQLiteファイルのヘッダに記録される。ランタイムはINDEXEDファイルを開くたびに設定されたモードを適用するため、
環境変数を切り替えれば既存のファイルも両方向に変換される。他のプロセスがそのファイルを開いている場合、SQLiteはエラーを返さずに変換を見送り、
ファイルは現在のモードのままとなる。これは異常ではなく、次にそのファイルが使われていない状態でOPENされたときに変換される。

WALモードでINDEXEDファイルを開いている間、SQLiteは同じディレクトリに次の2つの補助ファイルを維持する。

| ファイル | 用途 |
| --- | --- |
| `<ファイル名>-wal` | コミット済みだが主ファイルにまだ反映されていないデータを保持するログ |
| `<ファイル名>-shm` | 複数プロセス間の協調に使う、ログの共有メモリインデックス |

いずれも最後の接続が正常にクローズされた時点で自動的に削除されるため、正常にクローズされたINDEXEDファイルは従来どおり単一のファイルとなる。
`DELETE FILE` はこれらを主ファイルと一緒に削除する。

プロセスが異常終了した場合、`-wal` は残り、主ファイルにまだ反映されていないコミット済みレコードを保持する。
次のOPENでそれらは復元されるためデータは失われないが、次の2点に注意が必要である。

- `-wal` が存在するINDEXEDファイルをコピー・移動する場合は `-wal` も一緒に扱わなければ、そこに保持されているレコードが失われる。
  先にファイルをクローズしてしまうほうが確実であり、その場合は主ファイルだけをコピーすればよい。
- 異常終了したプロセスが残したファイルにはファイルロックも残る。上述の `cobj-idx unlock` で解除できる。

WALは共有メモリを必要とするため、NFSなどのネットワークファイルシステム上では動作しない。
INDEXEDファイルをそのような場所に置く場合は `COB_INDEXED_JOURNAL_MODE=DELETE` を設定すること。
